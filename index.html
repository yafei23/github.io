防火长城攻防时间线

THE GREAT FIREWALL · CAT & MOUSE · 1994 — 2025

防火墙方（GFW）封锁动作
翻墙方 反制技术
1990s — 建墙初期
1994
中国接入国际互联网
中国以 64 Kbps 专线正式接入 Internet，政府意识到需要"管理"互联网内容。
奠基
1997
《计算机信息网络国际联网安全保护管理办法》
首部互联网管理法规出台，明确列出九类禁止内容，确立"中央管控"原则。
立法
1998
金盾工程（Golden Shield）立项
公安部正式启动"金盾工程"，涵盖全国网络监控、内容过滤系统，外界称之为"防火长城（GFW）"。
系统化
1999
初步 IP 封锁 & DNS 污染
开始批量封锁境外敏感网站 IP，DNS 解析返回错误结果（污染），VoA等境外媒体率先遭屏蔽。
IP封锁
1994–1999
Web 代理 / 镜像站
用户通过境外 CGI 代理或镜像站访问被封内容，技术门槛极低，管控初期几乎畅通无阻。
代理
1998
手动修改 Hosts 文件
直接在本地 hosts 文件写入正确 IP，绕过 DNS 污染，是最原始的反 DNS 污染手段。
DNS绕过
2000–2008 — 规模扩张
2002
Google 首次被封
Google.com 遭短暂封锁（约两周），此后长期处于时断时续状态，标志着搜索引擎管控开始。
内容过滤
2003
金盾工程一期正式运营
全国骨干网部署关键词过滤，HTTP 明文流量中含敏感词即触发 TCP Reset 断开连接。
关键词过滤
2005
博客 / BBS 实名制试点
要求博客平台对用户实名注册，国内各大 BBS 展开实名制试点，论坛内容自我审查加剧。
实名制
2008
奥运前夕 Tor 遭封锁
北京奥运会前，GFW 封锁 Tor 公开节点 IP，同时强化 VPN 检测，境外媒体访问受限。
Tor封锁
2000–2003
商业 VPN 普及
PPTP / L2TP VPN 商业服务兴起，企业用户和科研人员大量使用，成为最主流翻墙方式。
VPN
2006
自由门（Freegate）广泛传播
法轮功相关团队开发 Freegate，利用动态 IP 池对抗封锁，在境内用户中大量流传。
动态IP池
2008
Tor Bridges 桥接节点
Tor 项目推出 Bridge 机制（不公开列入目录的节点），应对 GFW 对公开节点的批量封锁。
隐匿节点
2009 — 决定性封锁年
2009.3
YouTube 封锁（至今）
西藏骚乱周年前夕，YouTube 遭永久封锁，成为迄今最长的封锁记录之一。
永久封锁
2009.6
天安门事件 20 周年管控
Twitter、Hotmail、Flickr、Bing 等短暂封锁，大规模"敏感纪念日"管控模式成型。
节点封锁
2009.7
新疆事件 → 全面封锁
乌鲁木齐骚乱后，Facebook、Twitter 遭永久封锁，新疆断网数月，标志 GFW 进入"零容忍"阶段。
社交媒体封锁
2009
商业 VPN 市场爆发
Facebook、Twitter 封锁直接推动中国用户大量购买 ExpressVPN、HideMyAss 等境外商业 VPN 服务。
商业VPN
2009
SSH 隧道翻墙
技术用户大量采用 SSH -D 本地 SOCKS5 代理方式，利用境外服务器建立加密隧道。
SSH隧道
2010–2012 — DPI 深度包检测时代
2010.3
Google 退出中国大陆
谷歌因拒绝配合内容审查且遭受 Aurora 网络攻击，将搜索服务迁至香港，正式退出大陆市场。
谷歌封锁
2011
全面部署 DPI（深度包检测）
GFW 引入商用 DPI 设备（Cisco、Huawei），可识别 VPN 协议特征（OpenVPN handshake、L2TP/IPSec），开始主动干扰。
DPI
2012
OpenVPN 遭 DPI 精准识别
GFW 通过 TLS 握手指纹识别 OpenVPN，大量连接被 TCP Reset 强制中断，商业 VPN 大规模失效。
协议指纹识别
2012
敏感日期"流量暴风"
重大纪念日前后，GFW 对所有加密流量（含合法 TLS）实施速率限制，导致境外网站大规模不可用。
流量限速
2011
Shadowsocks 诞生（clowwindy）
中国程序员 clowwindy 开发 Shadowsocks，基于 SOCKS5 + 对称加密，流量特征极像随机数据，专为对抗 DPI 设计。
划时代工具
2012
obfs3（流量混淆）
Tor 项目发布 obfs3 混淆插件，将 Tor 流量伪装成随机字节流，对抗基于协议特征的 DPI 识别。
流量混淆
2013–2015 — Shadowsocks 黄金期 & 机器学习入场
2013
GitHub 首次遭封（后恢复）
GitHub 因托管翻墙工具源码遭短暂封锁；因影响国内开发者，数日后解封，但埋下后续多次封锁隐患。
附带伤害
2014
流量行为分析（统计识别）
GFW 引入基于流量行为的统计模型，通过数据包时序、大小分布识别 Shadowsocks 等"看似随机"的加密流量。
机器学习
2015
主动探测（Active Probing）
GFW 对疑似代理服务器主动发送探测包，通过服务器响应模式（replay attack）确认并封锁，极大提升准确率。
主动探测
2015
clowwindy 被"喝茶"
Shadowsocks 原作者 clowwindy 被警方约谈，随后删除代码库并宣布停止开发，震动翻墙社区。
开发者打压
2013
Shadowsocks 开源，快速扩散
SS 代码开源至 GitHub，各平台客户端（iOS/Android/Win/Mac）涌现，成为技术圈最流行翻墙工具。
开源爆发
2014
obfs4 + meek（域前置）
Tor 发布 obfs4 及 meek 插件；meek 利用 CDN（如 Google、Azure）进行域前置，让流量看起来像正常 HTTPS 请求。
域前置
2015
ShadowsocksR（SSR）fork 出现
breakwa11 开发 SSR，增加混淆插件（http_simple、tls1.2_ticket_auth），让流量伪装成正常 HTTP/TLS，应对行为分析。
协议混淆
2016–2018 — 全面收紧
2016
SNI 嗅探 & TLS 封锁
GFW 开始分析 TLS ClientHello 中的 SNI（服务器名称指示）字段，精确封锁特定域名而无需解密内容。
SNI封锁
2017.1
《互联网信息服务管理办法》修订
要求所有 VPN 服务商必须获得政府许可证，未经授权向公众提供 VPN 服务正式入罪。
立法打压
2017.7
breakwa11 被迫停止开发 SSR
SSR 作者 breakwa11 遭受 DDoS 和人肉搜索，被迫删库并宣布停止开发，官方收紧力度再次震动社区。
开发者打压
2017.8
苹果下架中国区 VPN App
Apple 应要求将 ExpressVPN 等数十款 VPN 应用从中国区 App Store 下架，移动端翻墙门槛大幅提升。
平台合规
2018
GitHub Pages / Raw 遭间歇封锁
GitHub 托管的翻墙配置文件、订阅链接频繁遭封；GFW 开始封锁 raw.githubusercontent.com 等子域名。
精准封锁
2016
V2Ray 发布（Project V）
v2fly 团队开发 V2Ray，引入 VMess 协议——带时间戳认证的加密协议，支持多路复用、动态端口等反追踪特性。
新一代协议
2016
域前置 (Domain Fronting) 流行
利用 Cloudflare、Google CDN 做域前置，让翻墙流量在外层 TLS 中显示 CDN 域名，绕过 SNI 封锁。
域前置
2018
Trojan 协议诞生
Trojan 将代理流量包裹在正常 TLS 层中，使用真实域名和证书，与普通 HTTPS 网站流量完全一致，极难识别。
仿真HTTPS
2019–2021 — AI 识别 & 生态分裂
2019
机器学习流量分类器上线
GFW 引入基于神经网络的实时流量分类，能以极低误报率识别 Shadowsocks / V2Ray VMess 等"无特征"流量。
AI识别
2019.6
六四 30 周年 大规模封锁
多款知名 VPN 工具同时失效，出现 "六四封锁周期" 现象——每逢六四前后 GFW 明显收紧，敏感日结束后回弹。
周期性强化
2020
Vmess 探测攻击
GFW 针对 VMess 协议发动重放攻击（replay），通过服务端响应差异确认节点，并自动加入封锁列表。
主动探测升级
2021
GitHub 间歇性封锁
GitHub 遭多次短时完全封锁（数小时至数天），引发国内开发者强烈反弹，GFW 每次均在舆论压力下恢复。
附带伤害
2019
V2Ray WebSocket + TLS + CDN
社区发展出 WS+TLS+Cloudflare 组合方案，将 V2Ray 流量完全伪装为 CDN 转发的 WebSocket HTTPS 连接。
CDN中转
2020
VLESS + XTLS 发布
Xray 团队推出 VLESS 协议和 XTLS（直接复用 TLS 内层数据，零二次加密开销），性能提升同时减少可识别特征。
XTLS
2021
Hysteria（QUIC-based）
基于 QUIC/UDP 的 Hysteria 协议出现，专门针对高丢包、高延迟环境优化（恰好对应 GFW 的 UDP 限速策略）。
QUIC协议
2022–2025 — Reality 时代 & 持续升级
2022
TLS 1.3 / ECH 被阻断研究
GFW 开始干扰 TLS 1.3 Encrypted Client Hello（ECH）试验，试图维持 SNI 可见性以实现精准域名封锁。
TLS攻防
2022
党代会 / 敏感事件超级管控
二十大前后出现史上最大规模 VPN 封锁潮，大量节点同时失效，部分商业服务被迫暂停提供中国用户服务。
政治性封锁
2023
AI 流量识别持续迭代
GFW 进一步强化基于时序分析的流量分类模型，能识别 Trojan、VLESS-XTLS 等"无特征"协议的微小行为差异。
AI升级
2024–2025
境外 IP 质量库实时更新
GFW 与主要云服务商 IP 数据合作，实现对 AWS/GCP/Azure/Cloudflare 出口 IP 的动态精准封锁。
云IP封锁
2022
Reality 协议（防主动探测）
Xray-core 推出 Reality，代理服务器直接借用真实网站的 TLS 证书和握手，让主动探测也无法区分真实服务器与代理。
反探测
2022
Sing-box 统一客户端
Sing-box 出现，单一内核支持 SS/V2Ray/Trojan/VLESS/Hysteria 等所有主流协议，降低使用门槛，加速协议生态整合。
生态整合
2023
Hysteria2 / TUIC
第二代 QUIC 翻墙工具（Hysteria2、TUIC）发布，进一步优化抗封锁能力和传输效率，应对 GFW 的 UDP 限速。
QUIC进化
2024–2025
去中心化 & Warp / 隧道多跳
Cloudflare Warp（基于 WireGuard）、多跳中转（落地机+中转机）架构流行，通过分散流量特征对抗精准封锁。
架构分散
攻防规律 & 核心洞察
GFW 核心策略演进
IP 黑名单 → DNS 污染 → 关键词过滤 → DPI 协议识别 → 流量行为分析 → 主动探测 → AI 机器学习分类
封锁升级路线
政治事件驱动周期
每逢六四、国庆、党代会、重大社会事件，GFW 明显收紧，事后部分回弹——"脉冲式"管控已成规律。
政治周期
翻墙技术演进路线
Web代理 → VPN → SSH隧道 → Shadowsocks → 混淆插件 → Trojan/VLESS → Reality/Hysteria → 去中心化多跳
反制路线
开发者代价
SS 作者 clowwindy、SSR 作者 breakwa11 均因警方压力被迫停止开发，中国翻墙工具开发者长期面临法律风险。
